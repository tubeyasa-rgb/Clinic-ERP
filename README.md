# Clinic ERP — Android client for Odoo

تطبيق Kotlin وJetpack Compose لإدارة فرص CRM وجهات الاتصال والمواعيد والأنشطة والمرفقات، مع واجهة عربية ودعم الوضع الداكن.

## التحميل المباشر

- [نسخة Android التجريبية APK](downloads/ClinicERP-debug.apk?raw=true)
- [ملفات المصدر المضغوطة](downloads/ClinicERP-improved-source.zip?raw=true)

الـAPK موقّع بمفتاح debug للتجربة، وقد لا يقبل التثبيت كتحديث فوق نسخة موقعة بمفتاح آخر.

## التشغيل

افتح المشروع في Android Studio، واستخدم JDK 21 وAndroid SDK Platform 37 (قد يظهر باسم 37.0) وBuild Tools 36.0.0. يشغّل Gradle Wrapper المرفق Gradle 9.5.0 ويتحقق من checksum الخاص بالتوزيعة. استخدم Run لتثبيت `app` على جهاز أو محاكي Android 7.0 أو أحدث.

في البيئة السحابية المجهزة:

```sh
cd /workspace/Clinic-ERP
python .cloud/build.py :app:testDebugUnitTest :app:assembleDebug
```

أدوات JDK وSDK والاعتماديات المحمّلة موجودة خارج المستودع تحت `/workspace`. السكربت يختار JDK كاملًا، ويستخدم بروكسي البيئة وشهاداتها الموثوقة بدون تعطيل فحص TLS. لا تحتاج لإنشاء Git worktree؛ استخدم نسخة المشروع الحالية في البيئة المعزولة.

## الاتصال بـOdoo

- استخدم رابط HTTPS واسم المستخدم وكلمة المرور، ويمكن تحديد اسم قاعدة البيانات مباشرة.
- إذا كان السيرفر يمنع عرض قواعد البيانات، أدخل اسم القاعدة يدويًا.
- يتطلب CRM تفعيل موديول CRM القياسي، والمواعيد تتطلب Calendar، وصلاحيات الحساب تتحكم في البيانات والعمليات المتاحة.
- تم الرجوع إلى كود Odoo الرسمي 19.0 و20.0 لواجهات JSON-RPC وفحص الصلاحيات وتغيير كلمة المرور. يلزم اختبار تكاملي فعلي على كل سيرفر قبل اعتماد التوافق في الإنتاج.
- الحسابات التي تتطلب تسجيل دخول تفاعليًا أو مصادقة متعددة العوامل قد تحتاج تدفق دخول منفصلًا؛ لا يوجد تدفق MFA داخل التطبيق حاليًا.

## التغييرات

- شاشة مواعيد يومية باختيار التاريخ والتنقل بين الأيام، وعرض كل المواعيد المتاحة للمستخدم كمنظم أو مشارك.
- تحويل مواعيد الجهاز إلى UTC عند الحفظ، وتحويلها إلى توقيت الجهاز عند العرض؛ المدد بالدقائق وتدعم عبور منتصف الليل.
- ربط المريض المختار بالمشاركين في الموعد بدل حفظ اسمه فقط.
- إزالة الاعتماد على حقل حضور `state` غير القياسي من الكاليندر، وإزالة الدمج الذي كان يحذف جهة الاتصال الثانية دون نقل العلاقات.
- بحث في CRM وجهات الاتصال بالاسم أو الهاتف أو البريد، وتحميل صفحات فرص CRM بدل التوقف عند أول 200 سجل.
- المحافظة على ارتباط جهة الاتصال عند تعديل الحالة، وتصحيح فك ترميز القيم النصية الاختيارية التي يعيدها Odoo بصيغة `false`.
- إظهار أخطاء JSON-RPC، ومنع تكرار عمليات الحفظ المتزامنة وإعادة التحميل بعد تسجيل الدخول.
- تحميل المرفقات بجلسة التطبيق إلى الكاش الخاص، وفتحها عبر FileProvider بصلاحية مؤقتة، بحد 30 ميجابايت للتنزيل و15 ميجابايت للرفع، مع قراءة الملفات خارج خيط الواجهة.
- تعطيل تسجيل أجسام طلبات الشبكة، وحصر إرسال cookie في أصل السيرفر المحدد، وتعطيل HTTP والنسخ الاحتياطي لبيانات التطبيق.
- تحسين الألوان والتنقل والعربية والوضع الداكن، وإصلاح تهيئة WorkManager لحقن Hilt وإضافة طلب إذن الإشعارات من الملف الشخصي.

## حدود الوظائف

جهات الاتصال عامة من `res.partner` وليست سجلات طبية مستقلة. المستخدمون مسؤولون عن الحالات وفرق CRM فرق متابعة؛ لا يفترض التطبيق أنهم أطباء أو فروع طبية. الحضور والغياب والملفات الطبية والفواتير والمخزون ليست ضمن سير العمل المطوّر هنا. لا توجد مزامنة دون اتصال. عرض المواعيد يومي وقائمة، وليس شبكة شهرية أو أسبوعية.

الاختبارات الآلية لا تغني عن تجربة الدخول والحفظ والصلاحيات على حساب Odoo تجريبي، أو مراجعة الواجهة على هاتف فعلي. لا تستخدم بيانات مرضى حقيقية في الاختبار.
